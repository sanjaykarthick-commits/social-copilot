# Social Copilot: guide for agents

Read this and `DESIGN.md` before changing code or UI. Then read `memory/INDEX.md` (lessons, decisions, preferences;
process in `memory-and-dreaming-context.md`). `AGENTS.md` (generated by Next.js) says to read the docs in
`node_modules/next/dist/docs/` first: this is Next.js 16, not the version you remember.

## What this is
A multi-platform social post scheduler: compose once, publish to several accounts, schedule on a calendar,
see analytics, answer comments. Built: Instagram, YouTube, LinkedIn and X adapters, composer with previews, calendar
(drag to reschedule), all-posts, dashboard analytics (per platform), comment inbox with replies, Instagram DMs
(inbox Messages tab: polling, 24-hour reply window, no new conversations), Instagram collaborators, token renewal,
settings (timezone), privacy/terms + Meta data-deletion callbacks, `npm run doctor`. **Not built (deliberately
deferred):** AI captions/replies, auto-reply rules, billing UI (`npm run plan:set`), email notifications, the other
platforms (shown as "Coming soon").

## Stack
Next.js 16 (App Router, Turbopack, `proxy.ts` not `middleware.ts`, **Cache Components off**: every dashboard
page is dynamic and reads the session), React 19, Tailwind 4, shadcn/ui on **Base UI** (triggers use
`render={<Button/>}`, not `asChild`), Clerk, Postgres + Drizzle (node-postgres), Inngest 4, ImageKit, zod 4, SWR,
dnd-kit, recharts. Tests: vitest.

## Rules that must not be broken
1. **No mock data in product code.** Unbuilt platforms are "Coming soon" with the connect button disabled. Demo data
   lives only in `scripts/seed-demo.mts` (local DB only).
2. **One plan key everywhere:** `free` / `premium`. Never `pro`. Limits live in `lib/plans.ts` only.
3. **Clerk id is text, internal ids are uuid.** `users.clerk_id` (text) vs `users.id` (uuid). Foreign keys use the uuid.
4. **Tokens are encrypted at rest** (`lib/crypto.ts`) and never leave the server. API responses use `PublicAccount`.
5. **The DB is the source of truth for scheduling.** `posts.inngest_event_id` is a per-schedule token; a run re-checks
   it when it wakes (`beginPublish`). Never "fix" a scheduling bug by trusting the Inngest run state.
6. **Send-new, then cancel-old** (`transition()` in `lib/posts.ts`): a post must never be left without a live run.
7. **"Post now" and "Schedule" share one function** (`publish-post`). Do not duplicate publishing logic.
8. **Validation is shared** (`lib/validation/posts.ts`) by the composer and the API. Change it in one place.
9. **Store UTC, render in the user's timezone** (`lib/time.ts`, `lib/calendar.ts`). Use the modern zone names.
10. **Errors:** API routes throw `AppError`/`PlatformError`; `handle()` turns them into `{ error: { code, message } }`.
11. **Media URLs must be under our ImageKit endpoint** (`lib/media.ts`): the server downloads them.
12. Environment is read lazily via `lib/env.ts` (`requireEnv`). Missing config must produce a readable error,
    never a crash at import time.
13. **Never claim a capability the platform did not grant.** `capabilities()` on an adapter says what a connection
    can do (e.g. LinkedIn stats need approval); the UI shows the reason instead of zeros or an empty list.
14. **Non-idempotent platform calls save progress first** (`saveState` -> `post_targets.publish_state`) so a retry
    resumes instead of re-uploading or posting twice.

## Adding a platform
1. `lib/platforms/<name>.ts` implementing `PlatformAdapter` (`lib/platforms/types.ts`).
2. Register it in `lib/platforms/index.ts`; set `implemented: true` and limits in `lib/platforms/meta.ts`;
   add its env check to `lib/platforms/config.ts`.
3. Add platform rules to `validateForPublish` and tests (see `tests/instagram-adapter.test.ts`: a stateful fake
   `fetch` that follows the documented protocol). Optional: `fetchMetrics`, `fetchComments`, `replyToComment`,
   `capabilities`, `refreshWindowMs` / `canRefresh` (token renewal policy).
4. Throw `PlatformError` with the right `kind`/`retryable`: `auth` = reconnect, `rate_limit`/5xx = retry,
   `validation`/`api` = show the message.
